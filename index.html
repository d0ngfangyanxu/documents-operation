01 / 是什么

它在公司业务中处于哪一段？

企业想给用户发 WhatsApp 消息时，需要先把标准消息做成模板、通过审核、在消息平台绑定正确的供应商模板，再由系统按业务事件发送。接手人守住的是“内容、名称、通道和实际发送保持一致”。

01 · 业务触发
用户发生一个动作注册、申请、产生账单，或进入营销目标人群
02 · 模板
写清要发什么验证、状态通知或营销；变量和按钮按类别设计
03 · 审核
确认能不能发YC / 供应商侧过审，msg 平台完成内部审核与绑定
04 · 发送
系统找到正确通道msgserver 对应模板名、供应商、变量和发送参数
05 · 结果
用户收到并行动送达、验证、查看状态、支付或转化；问题回流排查
02 / 为什么

先分清消息目的，后面才不会接错线

Authentication / aut

验证身份

用于登录、注册等 OTP 验证码。用户目标是完成身份验证；不能混入营销话术。

Utility / utl

告知已发生的事

申请审核、放款、账单、还款、结清等状态或必要提醒。内容与用户已有动作相关。

Marketing / ma

推动新的行动

优惠、召回、复购、产品推荐、充值或借款转化。即使开头像通知，只要带促转化目的，也应按营销审视。

判断技巧：看完整消息的真实目的，包括正文、变量、按钮和落地页。分类关系到审核、可用组件与后续结果评估。公开网页建议模板名可识别 App、类别、业务阶段及版本。
03 / Google 交接文档

审核员真正要走的步骤

指定文档描述的是“msg 平台的 WhatsApp 模板审核”。它接在业务登记和供应商模板准备之后，核心是找到正确的供应商模板名称，再绑定报备通道。

1. 看审核群通知

“whatsapp 审核群”出现待审核提示，代表有模板进入审核队列。先记录请求对应的 msg 侧模板名与业务场景。

2. 查业务登记表

贷前：复制 msg 侧模板名，在对应国家的贷前 WA 表格中搜索供应商侧模板名称；第一张表未找到，再查第二张。两张都没有，私信贷前业务确认是否登记。贷后：文档写明只对接 YC，供应商模板 ID 对应 msgserver 模板名称。

3. 审核并绑定

在审核页依次操作：审核 → 添加报备通道 → 填供应商与供应商模板名称 → 批量绑定 → 保存 → 下一步 → 提交。填写依据是业务登记表，不凭猜测补模板名。

4. 检查模板正文

文档给出的入口是“短信管理 → 短信模板 → 短信模板管理”，横向拉到最右侧，点查看图标。核对实际内容、变量和报备名称。

5. 处理错误

内容需驳回时，在模板管理最右侧点“撤销”。已审核通过却需更改模板名时，进入“WhatsApp 审核 → 审核通过 → 查询”，找到模板后重新审批。

贷前：查名路径

  1. 贷前 WA 登记表 1
  2. 备用登记表 2
  3. 两处都无记录：联系贷前业务，不自行生成供应商名。

一处原文需确认

交接文档写“如果有除 YC 外其他供应商，在正文只添加参数礸才能正常发送”。其中“礸”疑似输入错误，无法据此确定准确参数格式。执行前必须向文档负责人或消息平台确认。

04 / OTP 与切流

OTP 与“切流”要分开理解

已在材料中确认

OTP 是一次性验证码

它属于 Authentication 模板，用在注册、登录或身份验证。公开材料列出 Copy Code、Android One-tap Autofill 和 Android Zero-tap 等呈现方式；后两种依赖 App 配置。

术语解释，非内部 SOP

切流是调整请求走哪条发送路径

可以理解为把一部分 OTP 请求切到另一通道或配置路径，观察送达与验证结果，再决定扩大或回退。但指定交接文档并未说明上海快牛的具体切流操作，不可据此执行。

切流前必须问清为什么材料状态
原通道、目标通道与供应商确定究竟从哪切到哪未提供
切换维度：国家、App、场景、比例界定受影响用户未提供
审批人、执行人、配置入口明确变更权限未提供
观察窗口、指标、告警阈值判断是否改善或恶化未提供
回退触发条件与步骤失败时恢复原路径未提供
看指标时分三层：请求有没有进入发送系统 → 验证码有没有成功送达 → 用户有没有完成验证。送达率和验证完成率不是一回事；具体口径要以内部看板为准。
05 / 日常监控

YC 看质量，msgserver 审核

根据会议打字记录，日常工作可分为两条线：在 YC 观察号码和模板质量；在 msgserver 完成模板审核与映射检查。以下为整理后的操作顺序，具体判断阈值以团队口径为准。

YC / 账号质量

先看整体，再钻到异常

  1. 打开 YC，查看目标号码质量，并确认该号码是否有模板或营销消息。
  2. 进入质量较低的部分，分析近期变化；检查号码发送量是否明显波动。
  3. 如出现异常，将号码、时间、发送量变化及截图反馈到 YC 群。
模板判定 / 营销

从发送记录追到 WABA

  1. 按号码筛选，再筛选营销消息，查看下方发送记录。
  2. 识别实际发送的模板类型，核对是否被判为营销；贷款模板也要按内容和用途判断。
  3. 找到对应 WABA ID；若模板被判为营销且与预期不符，向业务方反馈。

审批后的四项复核

核对项检查内容
商户商户是否正确，是否对应本次业务需求。
模板与包模板是否正确、是否对应目标 App 包及业务场景。
发送时间营销和贷前通知的发送时间是否符合已确认的排期。
名称映射在映射表查 YC 上的模板名称；YC 与 msgserver 名称一致最便于追踪，不一致时必须确认正确映射。

发送结构是否符合预期

进入 WABA 运营监控，查看近期数据；将数据输入“模板发送结构计算器”，核对各类模板的发送比例是否符合预期。若偏差明显，带着时间段、号码、WABA ID 和结构变化与业务方沟通。

不要把短期波动直接当结论

会议记录指出：模板质量显示“未知”可能是阶段状态，尤其在反馈量较少时；质量会波动。记录中提到每周四触达，以及“巴基斯坦某账号 09 纯 OTP”案例。这些仅作排查背景，具体触达周期和“09”的含义需按账号资料确认。

异常反馈最少带上：国家、号码、WABA ID、模板名、商户、时间段、发送量与结构变化、YC 质量状态、发送记录截图，以及希望业务方确认的问题。
06 / 日常工作

一天通常会做什么？

接需求

确认业务目标、国家、App、用户动作、模板类别、语言、文案、变量和链接。检查业务是否完成登记。

审模板

看群消息，查对供应商模板名，核对内容，完成 msg 平台报备通道绑定。遇到缺登记或参数疑点就找业务方。

看结果

与研发/消息平台测试发送和变量替换；上线后根据模板名跟踪发送、送达、错误、点击或验证完成情况，并反馈异常。

每次变更都留痕：记录模板名、供应商名称、国家、App、审批结果、测试结果、上线时间与负责人。文档没有给出固定日报格式，以下反馈字段是接手建议。
07 / 反馈

让别人能复现、能判断、能处理

模板审核异常

  • msg 侧模板名、供应商侧模板名、国家、App、类别
  • 业务登记表位置与当前审核状态
  • 问题类型：找不到登记、内容不符、变量不符、绑定失败或误审
  • 截图/报错、影响范围、已联系的人、待回复问题

OTP 发送或切流异常

  • 发生时间、国家、App、验证场景
  • 请求量、发送量、送达量、验证完成量及口径
  • 错误码、失败样本、当前路径和变更记录
  • 是否达到内部告警或回退条件、执行人和下次更新时间
